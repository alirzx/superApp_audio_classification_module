# Deployment

Use `docker compose --env-file .env config --quiet` then `docker compose --env-file .env up --build -d`. The one-shot model-setup must complete before API. UI starts independently and shows an offline indicator when API cannot initialize. Avoid `docker compose down -v` unless deliberately discarding the model volume.

Local: API 127.0.0.1:8007, UI 127.0.0.1:8088. Production UI explicitly binds `192.168.4.209:8088` so approved LAN/VPN clients can access `http://192.168.4.209:8088`, provided the address exists on the host, TCP/8088 is permitted by the firewall, and VPN routes can reach the subnet. Keep API loopback-only. Protect UI with LAN/VPN firewall or authenticated HTTPS ingress and a strong unique API_TOKEN. Nginx's API token does not provide per-user auth.

A fresh named Docker model volume is created owned by root, so the one-shot model-setup initializes it as root with all capabilities dropped, writes a validated checkpoint and manifest readable by the unprivileged API, and leaves the API mount read-only. Repeated `compose up` verifies cached bytes and does not download again. Keep the named volume across deployments; `docker compose down -v` deletes it. Configuration enforces a production token and independent model digest. Build images use docker.arvancloud.ir for Python, Node and Nginx; Debian packages use signed primary/fallback APT mirrors, Python wheels use Liara then Chabokan mirrors, CPU PyTorch/vision/audio wheels use official CPU-only index, Alpine uses Liara then Huawei mirrors. Source-level configurations have been audited; real networked Docker builds are not yet validated.

Production `EXPECTED_MODEL_SHA256` must be populated from independently verified official checkpoint bytes because upstream release metadata does not publish a digest. First bootstrap requires GitHub release download access. Docker image builds require accessible Docker base images, Python package mirrors, PyTorch CPU wheel index and npm registry. Runtime needs no checkpoint network. API defaults to 2 CPUs, 1200 MB RAM, one Uvicorn worker, read-only filesystem and bounded tmpfs. UI defaults to 0.5 CPU, 256 MB RAM, non-root Nginx.

Verification: `docker compose ps -a`, logs for model-setup/API/UI, API `/health/ready`, UI `/healthz`, and real classification via Nginx. Run peak memory, p50/p95 wall time, accuracy, malformed audio and large-file tests on target hardware. GitLab CI was added by the deployment team and is preserved unchanged. It currently runs on master and invokes a remote Docker Compose build. Review its deployment security before exposing the UI beyond a restricted LAN/VPN.
